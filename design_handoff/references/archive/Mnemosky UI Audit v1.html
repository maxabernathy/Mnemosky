01   audit of the current surfaces

five opencv windows, one theme, no shell 01 / 04

Mnemosky currently ships five distinct UI surfaces, each well-made on its own, but without a shared shell or wayfinding. A user processing a video will move between the preprocessing preview, the processing dashboard, the review UI, and the debug view — four different mental models in one run.

surface · 01

Preview windows (× 3)

One per algorithm: --preview (Canny/Hough), show_radon_preview, show_nn_preview. Custom-drawn sliders, click-to-mark-trail, single-window layout.

strengthDense, algorithm-specific, immediate feedback. frictionThree separate windows with overlapping vocabulary. verdictevolve unify as Tuning mode with algorithm tabs.
surface · 02

Processing dashboard

ProcessingWindow — LIVE FRAME · TRAIL MAP · DETECTION TIMELINE · STATUS BAR. Throttled ≈20fps, redraws immediately on detections.

strengthQuadrant layout is legible; detection pulse is satisfying. frictionIsolated from review — no way to pin a moment for later. verdictkeep becomes the default Observe mode.
surface · 03

Review UI

Main frame + 280 px sidebar + 56 px status bar. Keyboard-driven (A/R/S/P/M/Z/L/Tab/Space/X/F/H/Q). HITL corrections feed Tier 1 + Tier 2 learners.

strengthKeyboard rhythm is the best part of the app. frictionThe shortcut vocabulary doesn't transfer to the previews. verdictkeep promote shortcuts to global grammar.
surface · 04

Debug view

--debug / --debug-only — side-by-side preprocessing, masks, classifications.

strengthEssential for tuning; the ledger surfaces why. frictionSeparate window, no link to the detection it explains. verdictevolve becomes an inline "inspect" panel on any frame.
surface · 05

Translation Ledger printout

End-of-run rejection audit (14 types across pipeline stages). Currently text-only in stdout + JSONL sidecar.

strengthThe STS-ness of Mnemosky lives here — its philosophical spine. frictionIt is invisible to anyone who isn't reading stdout. verdictpromote make it a first-class surface, not a footnote.
surface · 06

Config & learned params

~/.mnemosky/config.json, learned_params.json, rescue.json, platt.json, fusion_head.json, hypernet.json.

strengthProfiles-per-camera is the right mental model. frictionNo UI — you have to know the files exist. verdictnew a small "Profiles" pane in the shell.

What the theme already gets right

The existing palette (#1E1E1E bg, #2A2A2A panels, #D2D2D2 / #787878 text, #50FFC8 mint accent) plus the semantic markers (gold satellite, orange airplane, magenta anomalous) is already a coherent signal system. The shell should amplify it, not replace it. The one move worth making: warm it slightly — currently the mint reads acid against pure grey; softened against a warmer off-black it becomes calmer and easier to live with across long observation sessions.

02   master concept — The Observatory

one shell, four modes, one grammar 02 / 04

Mnemosky is an instrument for situated observation: the Ledger and observer-metadata flags make that explicit. The UI should make it felt. The proposal is a single windowed shell — The Observatory — that frames every run as a session at a telescope, with four modes that share a single grammar of frame, sidebar, status, and keyboard.

pillar · 01

One shell, four modes

Tune · Observe · Review · Inspect. Every surface today maps cleanly to one of these. Switching modes is a single keystroke (1/2/3/4); the frame stays, the sidebar reconfigures.

pillar · 02

The Ledger is always visible

A thin, quiet ribbon along the bottom counts rejections live, categorised. Click any category to dim the main frame and highlight only those rejections. The STS spine becomes an ambient presence.

pillar · 03

Observer card, not observer flags

Lat/lon/Bortle/FOV/notes collapse into a single card in the top bar — readable in one glance, editable inline. Situated knowledge made a literal object on screen.

pillar · 04

Organic feedback, scientific data

The loading, saving, and "learning…" states use the mercury-blob loaders. Detections, SNR bars, histograms stay precise and geometric. The warm organic moments only appear at transitions — they signal the instrument is thinking.

The four modes

mode · 1 · tune

Tune

Today's three preview windows, merged. One frame, algorithm tabs (default / radon / nn), sidebar of custom sliders grouped by pipeline stage. "Apply to session" commits to a run; "Save to profile" writes to learned_params.json.

mode · 2 · observe

Observe

Today's ProcessingWindow, promoted to default. Quadrants become a single frame with a floating trail-map minimap and a timeline ribbon. Pressing F freezes; . pins the current detection for review later.

mode · 3 · review

Review

Current Review UI, kept almost as-is — the keyboard rhythm (A/R/S/P/M/Z/L/Tab) is the best thing in the app. The new sidebar surfaces the learned-parameter delta inline so you can see your correction move the model.

mode · 4 · inspect

Inspect

Today's debug view, but bound to a single detection. Click a bbox in Observe or Review, press I — the frame splits into pre-processing, Canny mask, matched-filter response, and the classification decision tree, all for that one line.

type

Serif italic + monospace

Times New Roman italic for headings and wordmark — continues the reference image's liquid-serif personality. A monospace (JetBrains Mono / IBM Plex Mono fallback to system monospace) for all numeric, keyboard and metadata UI. Never mix cases on mono labels — always uppercase with tracked letter-spacing.

motion

Two motion registers

Meditative (4–6 s loops) for mercury-blob loaders and mode transitions. Responsive (100–200 ms) for every UI interaction — slider drag, mode switch, keypress feedback. Never blend the two; each has a clear role.

iconography

One icon grammar

Single-weight, 1.5 px stroke, slightly rounded terminals. The four mode icons (T/O/R/I) should start as typographic letterforms (pragmatic, matches the single-file ethos). Replace with glyphs later if and when the project moves to a richer GUI toolkit.

tone of voice

Instrument, not app

Copy is quiet and technical: "observing · frame 4,812", "gathering frames", "ledger · live". Never chirpy, never exclamatory. The wordmark sits in italic serif once, at top-left, and never shouts again.

next steps

from audit to instrument end
phase · 01

Ratify the shell

Pick one or two of the four modes (Observe feels the highest-value) and mock it at full fidelity before touching Python. Confirm the mode grammar with the team.

phase · 02

Port the theme, keep OpenCV

The shell can live inside OpenCV for v0.3.x — just a warmer palette, unified sidebar, and a live Ledger ribbon. No framework migration required.

phase · 03

Open the question of Qt / web

If the review + inspect modes demand richer interaction (draggable bboxes, inline histograms), consider a minimal Qt/PySide shell with OpenCV as the frame renderer. Defer the decision until after Phase 02.
